# AWS Clarity — Threat Model (v1.0.0 Hardening)

> **Important Scope & Honesty Statement**
> AWS Clarity is an independent open-source project. It has **not** undergone an independent third-party penetration test, SOC 2 audit, or security certification, and does **not** claim to be "fully secure."
>
> Throughout this document we strictly separate:
> - **Enforced:** Implemented in code or build configuration and verified by automated tests.
> - **Recommended:** Good practice the user should follow that AWS Clarity cannot enforce on their workstation or AWS account.
> - **Residual Risk:** Risk that remains even when all enforced and recommended protections are active.

## Trust Boundaries

1. **User Workstation & Local CLI (`aws-clarity`):** Trusted code running locally with the user's AWS credentials (`boto3` credential chain). Communicates only with official AWS endpoints and writes JSON reports to local disk.
2. **User's AWS Account:** Accessed strictly through allowlisted read-only APIs (`28` default actions, `34` with opt-in S3). AWS Clarity never modifies resources.
3. **Static Web Dashboard (CloudFront / GitHub Pages):** Serves static HTML/JS/CSS only. Parses imported local JSON reports in browser memory under production CSP `connect-src 'none'`. Never receives credentials or uploaded reports.

## Threat Matrix

| # | Threat | What Can Go Wrong | Likelihood / Impact | Existing Protection | Added Protection (Phase 1) | How It Is Tested | Residual Risk |
|---|---|---|---|---|---|---|---|
| 1 | **Wrong AWS account scanned** | User has multiple AWS CLI profiles or ambient env vars (`AWS_ACCESS_KEY_ID`) and scans production instead of sandbox, or confuses reports between accounts. | Medium / Medium | `sts:GetCallerIdentity` verified before scan; Account ID shown in report & top bar. | **Enforced:** Pre-scan confirmation block prints masked Account ID, masked Caller ARN, credential source/profile, scope, regions, and S3 cost status, requiring explicit `y/N` confirmation (or `--yes` in CI). No silent fallback if `--profile` is missing. | `test_phase1_hardening.py` (pre-scan confirmation prompt accept/decline, `--yes` flag, missing profile hard failure). | User may click `y` or pass `--yes` without verifying the last 4 digits of the account ID. |
| 2 | **Admin or root credentials used** | User runs the CLI as the AWS account root user or an `AdministratorAccess` role; any future bug or workstation compromise would have full account takeover blast radius. | High / High | Local-only execution (never handed to a vendor server); read-only CLI code. | **Enforced:** Hard root-user refusal (`:root` caller ARN blocked unless `--allow-root` is passed) in both `doctor` and `scan`. Explicit `WARN` (name heuristic only, zero extra IAM calls) when ARN contains `admin`/`administrator`, plus visible Step 2 onboarding callout + CloudFormation read-only role template (`infra/aws-clarity-readonly-role.yaml`). | `test_phase1_hardening.py` (root blocked by default, `--allow-root` override, admin heuristic warning without blocking or extra API calls, CloudFormation template matches policy). | **Recommended** read-only role cannot be enforced if the user runs with an admin role whose name does not contain `admin` (SCPs/permission boundaries determine real effective permissions). |
| 3 | **Restricted IAM permissions** | User runs with partial permissions; missing reads silently produce empty inventory and a misleading `100/100 HEALTHY` score. | High / Medium | `aws-clarity doctor` preflight; per-collector `ScannerError` & `CHECK_FAILED` tracking; Health Score withheld whenever coverage is `INCOMPLETE`. | **Enforced:** Pre-scan confirmation clarifies scope without claiming effective permissions; CloudFormation template and `aws-clarity policy` stay locked to the exact 28/34 actions via automated drift test. | `test_detection_coverage.py`, `test_local_cli.py`, `test_phase1_hardening.py` (policy/allowlist/CloudFormation parity). | If an SCP denies specific sub-calls inside a region, those checks show `INCOMPLETE` rather than `HEALTHY`, requiring the user to inspect Coverage. |
| 4 | **Unreachable AWS region** | An opted-in or network-blocked region (e.g., `me-south-1`) stalls the scan until timeout or hides regional resources. | Medium / Low-Medium | 3s TCP probe fast-fails unreachable regions, marks them `FAILED`/`INCOMPLETE`, and withholds the Health Score. | **Enforced:** Documented clearly in threat model & pre-scan confirmation; unreachable regions never produce silent `COMPLETE` coverage. | `test_unreachable_region_fast_fails_without_stalling_scan` (`test_detection_coverage.py`). | Users behind corporate proxies or with very large accounts (>90s budget) may still see partial scans and need `--regions` filtering. |
| 5 | **Secrets in resource tags** | Engineers occasionally place API keys, tokens, or passwords in EC2/EBS/VPC/EIP/NAT/Snapshot tags; storing full `Tags` arrays copies those secrets into the JSON report. | Medium / High | Sanitized export redacted some text, but full reports previously retained raw `Tags` arrays on EC2, EIP, VPC, IGW, NAT, EBS, and Snapshots. | **Enforced:** Field-level allowlisting at every collector boundary drops all `Tags` arrays immediately (extracting only the `Name` tag, sanitized and length-bounded). Free-text `Description` fields on Security Groups, Snapshots, Lambda, and CloudWatch Alarms are also dropped. | `test_phase1_hardening.py` canary test (`CANARY_TAG_TOKEN`, `CANARY_DESC_SECRET`) asserting zero occurrences in report JSON, stdout, stderr, and frontend exports. | If a user puts a secret inside the `Name` tag itself (or a bucket/resource name), it remains part of the resource identifier in the private full report (redacted on sanitized export). |
| 6 | **Secrets in Lambda environment variables** | `lambda:ListFunctions` returns `Environment.Variables` containing plaintext DB passwords or API keys in AWS responses. | High / Critical | `lambda_functions.py` did not copy `Environment`, but had no explicit canary regression test preventing future regressions. | **Enforced:** Explicit field allowlist in `lambda_functions.py` discards `Environment.Variables` values immediately, keeping only a `has_environment_variables` boolean (`True`/`False`). | `test_phase1_hardening.py` canary test (`CANARY_SECRET_LAMBDA_ENV`) asserting neither env var values nor secret keys appear in the report, terminal output, or frontend exports. | Secrets exist transiently in process memory inside boto3's parsed response dict until garbage-collected; workstation memory compromise is outside tool scope. |
| 7 | **Malicious imported JSON** | Attacker sends a crafted `.json` file with `__proto__` keys, huge payload (>25 MB), deep nesting, invalid types, or AWS credential fields to crash or pollute the browser dashboard. | Low-Medium / Medium | `reportImporter.js` enforces 25 MB limit, depth-16 recursion limit, `__proto__`/`constructor`/`prototype` stripping, control-char stripping, and credential-field blocking. | **Enforced:** Verified with Phase 1 canary + security tests; CSP `connect-src 'none'` prevents exfiltration even if parsing fails unexpectedly. | `verify-frontend-invariants.mjs` (malformed JSON, prototype pollution, credential-key blocking, demo fixture rejection). | Browser memory/CPU DoS from a valid 24 MB JSON file remains possible on low-memory devices. |
| 8 | **Malicious resource names (HTML/script injection)** | An AWS resource name, SG name, or imported JSON field contains `<script>alert(1)</script>` or `=CMD|...` spreadsheet formulas. | Low-Medium / High | React JSX auto-escapes text nodes (no `dangerouslySetInnerHTML`); CSV exporter neutralizes leading `=`, `+`, `-`, `@`, `\t`, `\r` via `neutralizeCsvCell()`; CSP `script-src 'self'`. | **Enforced:** Canary + XSS string test verifies script/HTML payloads in resource names remain inert plain text and formula payloads are neutralized in CSV exports. | `verify-frontend-invariants.mjs` + `verify-phase1-canary.mjs`. | Users opening raw unescaped JSON in external third-party tools must rely on those tools' escaping. |
| 9 | **Compromised package / dependency** | A compromised PyPI/npm transitive dependency or tampered wheel executes malicious code on the user's workstation or browser. | Low / Critical | Pinned `boto3==1.42.66` / `botocore==1.42.66`; `npm audit` (0 vulns); `SHA256SUMS.txt` published on GitHub Releases. | **Enforced:** Zero-telemetry socket test proves CLI makes zero non-AWS network calls; client-layer API guard blocks any unlisted AWS operation even if a collector is modified. **Recommended:** Users should verify `SHA256SUMS.txt` and inspect source before installing. | `test_phase1_hardening.py` (socket/network allowlist test + API operation allowlist test). | Checksums detect tampering after download only if users verify them; checksums are **not** cryptographic signatures. Supply-chain compromise of a maintainer account or upstream PyPI dependency remains a residual risk. |
| 10 | **Release artifact differs from source** | A tagged release wheel (`v1.0.0`) lags behind `main` or contains unexpected local files/reports. | Medium / High | GitHub Actions builds and publishes artifacts from tagged commits cleanly in CI. | **Enforced:** Documented gap between `v1.0.0` (`5917933`) and `HEAD` (`64671bd`); audited in Phase 4 before any new tag is proposed (owner-approved only). | CI workflow `.github/workflows/ci-release.yml` clean-venv wheel test + Phase 4 artifact diff. | Until a new release tag is published by the owner, `v1.0.0` wheel reflects commit `5917933`, not subsequent branch commits. |
| 11 | **User shares an unredacted report** | User posts full `aws-clarity-report.json` or full CSV in a public GitHub issue, Slack channel, or ticket, exposing Account IDs, ARNs, public IPs, and IAM usernames. | High / High | Local file written with `0600` on POSIX; Export Modal shows explicit Privacy Warning and defaults recommendation to **Sanitized JSON**; `reportSanitizer.js` redacts Account IDs, ARNs, names/IDs, and IPs. | **Enforced:** Minimized collectors strip tags, descriptions, RDS endpoints, Lambda env vars, and full IAM policy documents from **even full private reports**, dramatically reducing blast radius if a full report is accidentally shared. | `test_phase1_hardening.py` + `verify-frontend-invariants.mjs` + `verify-phase1-canary.mjs`. | **Residual Risk:** Sanitized export is **best-effort redaction, not guaranteed anonymization**—unique naming patterns or custom text could still identify an organization; users must review before external sharing. On Windows, `0600` POSIX mode does not apply; report files inherit standard Windows user directory ACLs. |
| 12 | **Rule mislabels a legitimate production resource** | A heuristic (stopped EC2, empty provisioned DynamoDB table, active NAT Gateway, >90d unmodified Lambda, default SSE-S3, orphaned snapshot, `INSUFFICIENT_DATA` alarm) raises a red/amber alarm and erodes trust. | Medium / Medium | Heuristic rules (`S3-004`, `LAM-001`, `NAT-002`, `EC2-001`, `DDB-002`, `SNAP-001`, `CW-002`) emit `INFO` (`0` pts deducted, resource stays `HEALTHY`); empty default VPCs, read-only `Resource: *` policies, and AWS service-linked roles pass cleanly. | **Enforced:** Verified by regression tests in `test_detection_coverage.py` and full rule audit planned in Phase 2. | `test_reclassified_info_rules_and_three_categories`, `test_iam_context_aware_read_only_vs_write_and_conditions`. | Some legitimate edge cases (e.g., intentionally public static-website S3 bucket or internal non-Org cross-account role without `ExternalId`) can still trigger findings and require human judgment. |
| 13 | **Remediation advice causes an unnecessary or destructive change** | A user blindly deletes a NAT Gateway, EBS volume, IAM access key, or security group rule and breaks production traffic or CI pipelines. | Medium / High | Strictly read-only (zero auto-remediation); destructive-risk findings (`IAM-010`, `NAT-002`, `EIP-001`, `EBS-002`, `EC2-001`, `SNAP-001`, `DDB-002`) explicitly warn about dependencies, backups, and IaC state before making manual changes. | **Enforced:** No mutation API exists in the allowlist or codebase; full remediation accuracy audit scheduled in Phase 2. | `test_phase1_hardening.py` (static + runtime mutation block tests). | Human error when applying manual changes in the AWS Console/CLI remains the operator's responsibility. |
