# Troubleshooting

## 1. Expired AWS SSO / IAM Identity Center Token
**Symptom:** `Your AWS SSO / IAM Identity Center token has expired.`
**Fix:** Refresh your session and verify identity:
```bash
aws sso login --profile my-profile
aws sts get-caller-identity --profile my-profile
```

## 2. Missing Permissions (`aws-clarity doctor` exits with code 2)
**Symptom:** One or more services show `[MISS] ... MISSING`.
**Fix:** Generate the least-privilege policy (`aws-clarity policy --zero-cost-only` or `aws-clarity policy`) and attach the missing read-only actions to your IAM role or IAM Identity Center permission set.

## 3. S3 Shows `SKIPPED_OPTIONAL` in Coverage
**Cause:** By design, S3 checks are skipped on default scans so AWS Clarity never generates S3 API request charges without explicit consent.
**Fix:** Re-run with `--include-s3-checks` and confirm the cost prompt (or pass `--confirm-s3-request-costs` in non-interactive shells).

## 4. Health Score Shows "Health score unavailable — assessment incomplete."
**Cause:** At least one mandatory service, opt-in region, or resource check failed (for example, an unreachable opt-in region or missing IAM permission).
**Fix:** Open **Coverage report** in the dashboard to inspect the exact failing service, region, and required IAM permission, resolve it (or scan specific regions via `--regions us-east-1,eu-west-1`), and re-import the new report.

## 5. Browser Blocks Report Import
- **"Invalid JSON file":** Ensure you selected the `.json` file generated by `aws-clarity scan --output ...`, not a CSV export.
- **"Blocked import: this file appears to contain AWS credential fields":** Never import AWS credential files or STS output; only import reports created by `aws-clarity scan`.
- **"Demo fixtures cannot be imported":** Use **Explore Demo** directly for synthetic sample data.
