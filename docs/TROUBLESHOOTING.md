# Troubleshooting

Every common setup, AWS authentication, scanning, and browser import issue—with **what happened**, **why**, and **what to do next**.

## 1. Python 3.10+ Is Missing
- **What happened:** `python3: command not found`, `py: command not found`, or `requires-python >=3.10` error.
- **Why:** AWS Clarity requires Python 3.10 or newer.
- **Next:** Install Python 3.10+ from `https://www.python.org/downloads/` (on Windows, check "Add Python to PATH"), restart your terminal, and verify with `python3 --version` (macOS/Linux) or `py --version` (Windows).

## 2. `pipx` Is Missing or Installation Fails
- **What happened:** `pipx: command not found` or wheel installation fails.
- **Why:** `pipx` is optional and not installed by default on most machines, or network/proxy settings blocked downloading `boto3`.
- **Next:** Switch to the built-in Python virtual environment method (`python3 -m venv ~/.aws-clarity && ~/.aws-clarity/bin/pip install .` on macOS/Linux, or `py -m venv "$HOME\.aws-clarity"` on Windows PowerShell). If behind a corporate proxy, configure `HTTPS_PROXY` / pip certificate settings first.

## 3. AWS CLI Profile Not Found
- **What happened:** `AWS CLI profile '<name>' was not found in ~/.aws/config or ~/.aws/credentials.`
- **Why:** The profile name is misspelled or not configured. AWS Clarity intentionally refuses to fall back to default credentials so it never scans the wrong AWS account.
- **Next:** Run `aws configure list-profiles` to see valid profile names, then re-run with `--profile <exact-name>`.

## 4. Expired AWS SSO / IAM Identity Center Token
- **What happened:** `Your AWS SSO / IAM Identity Center token has expired or could not be retrieved.`
- **Why:** Short-lived SSO sessions expire periodically for security.
- **Next:** Refresh your session and confirm identity:
  ```bash
  aws sso login --profile my-profile
  aws sts get-caller-identity --profile my-profile
  ```

## 5. AWS Account Root Credentials Refused
- **What happened:** `Refused to run with AWS account root credentials (arn:aws:iam::********XXXX:root).`
- **Why:** AWS account root credentials have unrestricted control over your account and billing.
- **Next:** Switch to a dedicated read-only IAM role or IAM Identity Center permission set (see `docs/IAM_PERMISSIONS.md` and `infra/aws-clarity-readonly-role.yaml`).

## 6. Missing AWS Permissions (`aws-clarity doctor` exits with code 2)
- **What happened:** One or more services show `[MISS] ... MISSING` or coverage lists `AccessDenied`.
- **Why:** Your active IAM role or permission set lacks one or more of the 28 default (or 6 optional S3) read-only actions.
- **Next:** Generate the exact least-privilege policy (`aws-clarity policy --zero-cost-only` or `aws-clarity policy`) and attach it to your dedicated read-only role or permission set.

## 7. Region Unavailable or Timed Out
- **What happened:** Coverage shows `INCOMPLETE` and `Failed Regions` lists one or more regions, and the health score displays `"Health score unavailable — assessment incomplete."`
- **Why:** An opt-in region may be restricted by an SCP, unreachable, or a large account exceeded the 90-second default scan budget.
- **Next:** Open **Coverage** in the dashboard to inspect the exact failing service/region, or scope the scan to specific active regions:
  ```bash
  aws-clarity scan --profile my-profile --regions us-east-1,eu-west-1 --output aws-clarity-report.json
  ```

## 8. Account Shows 0 Discovered Resources
- **What happened:** The dashboard reports 0 resources.
- **Why:** Either the scanned regions genuinely contain no resources across the 9 default services (or S3 was skipped as optional), **or** collection failed due to permissions/timeouts.
- **Next:** Check the coverage status banner: if `INCOMPLETE`, open **Coverage** to inspect failures. If `COMPLETE` and you expected S3 buckets, re-run with `--include-s3-checks`; if you expected resources in another service (e.g. EKS, Route 53), check **Known Limitations** in `docs/SUPPORTED_SERVICES_AND_RULES.md`.

## 9. S3 Shows `SKIPPED_OPTIONAL` in Coverage
- **What happened:** S3 is listed as `SKIPPED_OPTIONAL` (never marked healthy).
- **Why:** By design, S3 checks are skipped on default scans so AWS Clarity never generates AWS S3 API request charges without explicit consent.
- **Next:** Re-run with `--include-s3-checks` and confirm the cost prompt (or pass `--yes --include-s3-checks --confirm-s3-request-costs` in non-interactive shells).

## 10. Browser Rejects Report Import
- **"Invalid JSON file":** Select the `.json` file generated by `aws-clarity scan --output aws-clarity-report.json` (not a CSV export or truncated file).
- **"Blocked import: this file appears to contain AWS credential fields":** AWS Clarity refuses files containing `SecretAccessKey`, `SessionToken`, or temporary STS credential patterns so secrets are never imported into the browser.
- **"Report file exceeds the 25 MB local browser safety limit":** Re-run `aws-clarity scan` with `--regions <subset>` and `--compact`.
- **"Demo fixtures cannot be imported":** Use **Explore Live Demo** on the home screen for synthetic sample data.

## 11. Scan Comparison Withheld or Findings Marked "Unverified"
- **What happened:** Scan Diff displays `Comparison withheld` or lists prior findings under `? Unverified` instead of `✓ Resolved`.
- **Why:** Comparison is withheld when two reports belong to **different AWS accounts** (to prevent misleading diffs), and prior findings are marked `Unverified` when the newer scan was `INCOMPLETE`, failed a rule check (`CHECK_FAILED`), or skipped an optional service (such as S3) that was previously scanned.
- **Next:** Import two complete reports from the **same AWS account** with matching service/region scope to verify resolved findings.
